## 查明与修复

### 1. 专用 Key 的授权选错模型

实际收到：

```text
AccessDenied: Access denied by API-Key restrictions.
```

创建时误选了 **Fun-ASR语音识别**，对应录音文件模型 `fun-asr`，没有覆盖 App 的 `fun-asr-realtime`。

已编辑同一把专用测试 Key，重新打开编辑页确认保存的权限仅为：

- `fun-asr-realtime`：Fun-ASR 实时语音识别
- `qwen-plus`：翻译

没有重置 Key、修改已有业务 Key，也没有改成全部模型权限。用户不需要再次填 Key。接入地址与 Key 仍须属于相同地域/业务空间。

### 2. 首次错误被关闭连接的回调覆盖

原先 `AccessDenied` 被归类为 Response；取消被拒绝的 socket 后，随后的 `onFailure(Socket is closed)` 又可能将后续 `feed()` 看到的错误改成 Network。

现在：

- `AccessDenied` / 权限拒绝与 HTTP 403 映射到独立的 Permission 错误。
- 一旦失败或完成，就不再覆盖原始结果。
- UI 明确提示检查模型授权、业务空间和 IP 白名单，而不是统称无效结果或网络故障。

### 3. 5 秒 Ping 看门狗误伤

曾实际收到：

```text
SocketTimeoutException:
sent ping but didn't receive pong within 5000ms
```

取消这个过短的客户端 Ping 策略，保留任务结束的 10 秒应用层期限、录音上限、有界发送队列与显式取消；不增加自动请求重试，也不静默丢音频。

录音仍是 20 ms PCM16LE 帧，网络侧合并成 100 ms 消息，结束前发送完整尾帧，减少小消息开销。

### 4. 临时 begin_time 改动导致残词堆积

首次连通后，原文一度出现「好好ello world 最Hello World…」。此前将每个临时 `begin_time` 当成新句；当模型调整临时起点时，旧草稿残留在最终文本里。

依据 DashScope SDK 的 `is_sentence_end` 规则修复：`end_time != null` 才是最终句。临时句单独替换，最终句按起点提交/去重；任务结束时仍未完成的草稿不能冒充最终结果。修复后官方样例原文完整且没有残片。

## 复现

先在 App 内保存服务配置。测试会产生云端用量，不接受 Key 命令行参数，也不从聊天读取 Key。

构建并安装主包和测试包：

```powershell
./gradlew assembleDebug assembleDebugAndroidTest
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
```

准备 16 kHz / PCM16 / mono 样例：

- 官方文件：https://dashscope.oss-cn-beijing.aliyuncs.com/samples/audio/asr_example.wav
- 英文样例可用 Windows System.Speech 的 Microsoft David Desktop 生成，内容必须与上面的英文原文一致，输出格式为 16000 Hz / Sixteen / Mono。
- 本次使用的本地文件为 `docs.local/asr_example.wav` 和 `docs.local/parley-english.wav`；音频不纳入仓库。

```powershell
adb -s SERIAL push docs.local/asr_example.wav /data/local/tmp/parley-asr-example.wav
adb -s SERIAL push docs.local/parley-english.wav /data/local/tmp/parley-english.wav
adb -s SERIAL shell am instrument -w -r -e class io.github.evative7.parley.CloudPipelineTest -e runCloudTests true io.github.evative7.parley.test/androidx.test.runner.AndroidJUnitRunner
```

测试期间保持手机解锁、Parley 在前台。若设备限制测试进程拉起界面，可在第二终端执行：

```powershell
adb -s SERIAL shell am start -W -n io.github.evative7.parley/.MainActivity
```

检查输出包含 `OK (2 tests)`，不能只看 adb 的进程退出码；`am instrument` 在用例失败时也可能返回 shell 成功。不传 `runCloudTests=true` 时跳过计费测试。

## 补充：识别延迟排查（2026-10-31）

诊断回调加入相对会话打开的毫秒时间戳后，在 REDMI K90 Pro Max 上复测同两段样例：

| 阶段 | 每次按下新建连接（原实现） | 预先建立连接（现实现） |
| --- | --- | --- |
| 按下 → `task-started` | 2.3 s / 3.2 s | 0.14 s |
| 按下 → 首个部分转写 | 2.7 s / 4.3 s | 0.7 s / 1.0 s |
| 松手 → 最终原文 | 0.75 s / 2.8 s | 0.96 s / 1.9 s |

- 主要瓶颈是每次按下才进行 TLS + WebSocket 握手（0.5–3 s）。这期间录音只能排队，而服务端按实时速度识别，积压的音频会延后最终结果。
- 现在界面可见时预先打开一条空闲 WebSocket（不发送 run-task、不发送音频，不计费），按下时直接接管；服务端约 62 s 后会关闭空闲连接，届时自动重建一条备用连接。退到后台时关闭。备用连接在 task-started 前被关闭时，会话透明地重连一次，已缓存的音频不丢失。
- 翻译服务在界面可见时发一次不带 Key 的 HEAD 请求以预热 TLS 连接；ML Kit 语言模型在 ViewModel 创建时预加载。
- 剩余的松手后等待主要来自 `fun-asr-realtime` 服务端收尾（同一段音频 0.8–7.6 s 不等），客户端无法消除；可尝试 `paraformer-realtime-v2` 或 `fun-asr-realtime-2026-02-28`（需要在 Key 上授权对应模型）。
- 单次样例测量，不是平均值或 P95。复现空闲连接寿命：`-e runCloudTests true -e probeIdle true`。
